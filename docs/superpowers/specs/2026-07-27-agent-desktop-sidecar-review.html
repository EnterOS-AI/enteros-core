3SSOT contract + abstraction

The contract IS the abstraction seam

Author contracts/tool/computer-use.contract.json in the SDK → codegen molcontracts.ComputerUseContract → workspace-server consumes + value-pins it (precedent: mcp_plugin_delivery_contract.go · MatchesSSOT). Zero new codegen machinery — rides the existing drift-gate + module-bump rails. It pins the coordinate geometry, action enum, control-server protocol, and the screenshot result shape so every consumer agrees. Extracting to a plugin later is a refactor behind this contract.

Backend-neutral SidecarProvisioner

One interface, three backends behind the existing …Auto dispatcher: Local (Docker) — ships first CP (cloud) — deferred, returns "unavailable" k8s — at migration. A missing backend is a clean per-tier availability gate (feature absent, nothing broken), not a build break. Self-host is fully functional standalone.

5Security-first (the prerequisite)

Per-workspace network — mandatory before ship

Each workspace + its desktop on a dedicated network; backend infra (Postgres/Redis/MinIO/LiteLLM) on a backend-only net; sidecar internet egress through a domain-allowlist proxy. Set a Redis password now. Today everything shares one flat molecule-core-net with passwordless Redis — a compromised browser is a cross-tenant pivot.

Privileged-tenant reality

Tenants are T3/T4 (host-root capable) by design, so the sidecar being non-root isn't isolation alone. Enable daemon userns-remap (also fixes cross-tenant uid collisions); cap-drop + seccomp + no-new-privileges on the sidecar, reconciled with Chrome's sandbox (no --no-sandbox).

Governance — capability is authorization + AI escalation (decision 4)

No per-action human confirmation. The boundary is what the agent is provisioned to reach: if it isn't allowed, it never gets the credential — so credential scoping is the primary control (each task gets only the logins it needs). Domain allowlist per task; treat pages as untrusted. Serious/ambiguous matters escalate agent → team-lead → platform agent → user, reusing the existing parent_id hierarchy + A2A messaging + send_message_to_user. Full navigation/input audit + real-time kill.

Secrets at rest — deferred (decision 2)

No volume encryption exists in the codebase; we do not claim it. The profile volume ships unencrypted at rest for now (honest posture to operators); encryption is a tracked follow-up RFC — revisit before any regulated-data deployment.

7Lifecycle fixes

  • Idle = agent control-server activity + a computer-use lease; re-check under the lifecycle mutex before teardown (the agent opens zero VNC connections).
  • Non-blocking cold start; pre-build the sidecar image at tenant-provision so a wake is create-only, never a 12-min local build.
  • Memory/oom caps + per-node admission; sidecar oom_score_adj above the tenant so pressure sheds the desktop, never the agent.
  • Graceful ContainerStop (SIGTERM + flush) — never force-remove (corrupts the profile). Restart policy no; recover crashes in the platform (on-failure banned).
  • Credential-volume reap in the sweeper and inline delete; wsdesk-<id> naming so it can't be mis-parsed.

8Sequencing — why "self-host first"

Not feature coupling — ownership. Local/Docker: workspace-server launches the container itself (all code here). Cloud: the control plane launches it, and has no scale-to-zero primitive today — net-new work in a separate repo. So the backend we own ships now; the cloud backend is a clean availability gate that lands when CP wires its half. On k8s without the backend, the desktop is absent on that tier (not slow) — nothing else is affected.

11Resolved decisions

1 · Co-located ✓

Pod (k8s) / VM (cloud) / lifecycle-coupled sibling (self-host). Self-host gets true container-level scale-to-zero; cloud is process-level until CP adds independent scheduling.

2 · Encryption deferred ✓

Honest unencrypted posture now; tracked follow-up RFC; revisit before regulated data.

3 · Re-point via 3-layer split ✓

Actuator (sidecar control server) · enforcement gateway (platform-Go) · agent tool (re-pointed a2a_tools_desktop.py, types generated from the SSOT contract). One surface, plugin-extractable.

4 · Capability = authorization ✓

No human gates; tight credential scoping + AI escalation chain + audit.
